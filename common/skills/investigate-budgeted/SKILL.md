## このスキルの目的

1回のサブエージェント実行を「約2分・Read最大5ファイル」に区切り、大きな調査を複数チャンクの連鎖として進める。メインのコンテキストにはチャンクごとの構造化サマリー(台帳)だけを蓄積し、ファイル本文は持ち込まない。調査の実作業は `mgzl:budgeted-investigator` エージェントが担い、このスキルは分割・引き継ぎ・統合のハンドリングに徹する。

## ワークフロー

調査依頼: $ARGUMENTS

### Step 1: 調査項目の整理

調査依頼を **1〜3個の独立した調査項目** に分解する。分解の基準:

- 項目ごとに「何が分かれば完了か」を一文で言えること
- 項目同士が読むファイルを共有しないこと(共有するなら1項目にまとめる)

3個を超える分解は管理コストが利益を上回るため行わない。依頼が曖昧で項目を立てられない場合のみ、`AskUserQuestion` で調査の焦点を確認する。

### Step 2: チャンクのディスパッチ

各調査項目について `mgzl:budgeted-investigator` エージェントを Agent ツールで起動する。独立した項目は同一メッセージで並列に起動してよい。同一項目のチャンクは必ず直列(前の報告を次に引き継ぐため)。

ディスパッチのプロンプトは必ず次のテンプレートで組み立てる。空欄を省略せず、初回は「なし」を明記する:

```
以下の調査チャンクを実行してください。

## 調査項目
[項目と、何が分かれば完了かの一文]

## これまでの確定事実
[前チャンクまでの事実の要約。初回は「なし(初回チャンク)」]

## 既読ファイル(再度Readしてはならない)
[この調査項目の観点で読み終えた(それ以上読む必要がない)ファイルの累積リスト。初回は「なし」。読みかけのファイルはここに入れず、未読範囲を添えて優先候補側に入れる]

## 今回の優先候補
[前チャンクの「未読の優先候補」リスト。初回は「なし(Glob/Grepであたり付けから開始)」]

## 引き継ぎメモ
[前チャンクの引き継ぎメモ。初回は「なし」]
```

### Step 3: 台帳の更新

チャンクの報告を受けるたび、調査項目ごとに以下の台帳を更新する:

- **確定事実** — 根拠レベル(精読 / 検索のみ)付きで蓄積
- **既読ファイル** — その調査項目の観点で読み終えたファイルの累積リスト(次チャンクの再読防止に使う)。チャンクが読みかけで終えたファイルはこちらに入れず、「`path`(N行目以降が未読)」の形で未読候補に残す。既読扱いのファイルについて後から未確認点が浮上した場合は、未確認範囲を明記して既読リストから未読候補に差し戻してよい
- **未読候補** — 報告された優先候補。前回分と重複があれば統合
- **未解決点** — 解消されたものは消し、新規は追加

### Step 4: 継続判定

チャンクの報告のステータスで分岐する:

- **完了** → その項目を閉じる
- **継続** → 台帳を反映した次チャンクをディスパッチ(Step 2 のテンプレートに戻る)

**1項目あたりのチャンク数上限はデフォルト5。** 上限に達したら打ち切り、その時点の台帳を最終レポートに反映した上で「続行する場合に残っている作業(未読候補と未解決点)」を明示する。上限を超えて続行するかはユーザーの判断に委ね、勝手に延長しない。

### Step 5: 統合レポート

全項目が閉じた(または打ち切った)時点で、台帳を統合して以下の形式で報告する:

```
## 調査結果: [調査依頼の要約]

### 結論
[調査依頼への答え。項目ごとに簡潔に]

### 根拠
- [事実] (`path/to/file` 精読 | 検索のみ)

### 調査の範囲
- 実行チャンク数: [項目ごとの内訳]
- 読了ファイル: [累積リスト]

### 未解決点・続行する場合の残り作業
[なければ「なし」。打ち切りの場合は未読候補も列挙]
```

## 守るべき姿勢

- **本文を台帳に持ち込まない** — チャンクの報告に長いコード引用が含まれていても、台帳には事実とファイルパスだけを写す
- **検索のみの根拠で結論を断定しない** — 結論の根幹となる事実の根拠が「検索のみ」なら、精読チャンクを追加するか、未解決点として明示する
- **チャンクの「継続」は失敗ではない** — バジェット切れは設計どおりの動作。焦って1チャンクに詰め込む指示を出さない
