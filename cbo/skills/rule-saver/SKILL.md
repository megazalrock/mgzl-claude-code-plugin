## コンテキスト

- 引数: $ARGUMENTS

## 目的

未修正バグ・既知の落とし穴の知見を、対象プロジェクトの `.claude/rules/mgzl/` 配下に恒久ルールファイルとして定着させる。

## ワークフロー

### Step 1: 入力ソースの判定

`$ARGUMENTS` から `-y`（確認スキップフラグ）を取り除いたうえで判定する。`-y` は入力ソースではない。

- **残りの引数が空でない場合**: それが指すメモファイル、または対象の説明を入力とする
- **残りの引数が空の場合**: 現在のセッションの会話内容から、ルール化すべき未修正バグを抽出する
  - 抽出対象は「このセッション内でコード上の根拠を伴って特定した未修正バグ・落とし穴」に限る。実装を読んで「こうなるはず」と推測しただけのものは含めない
  - このセッション内で既に修正済みのものは含めない
  - 候補が 0 件なら、その旨を報告して終了する

**セッション由来モードは会話履歴が入力であるため、メインセッションで実行する。この抽出をサブエージェントへ委譲してはならない**（サブエージェントは会話履歴を持たないため）。
引数でメモのパスが指定されたモードでは、Step 3 の裏取り調査をサブエージェントへ委譲してよい。

### Step 2: 保存先の決定

保存先は `${CLAUDE_PROJECT_DIR}/.claude/rules/mgzl/`。ディレクトリが無ければ作成する。

既存のルールファイルを一覧し、frontmatter の `paths` が今回の対象と重なるファイル、または同一の対象を扱っているファイルがあるかを確認する。

- **重なるものがある場合**: そのファイルへバグの節を追記統合する。既に書かれている事象は重複して書かない。追記により削除条件や `paths` に変更が要るならそれも更新する
- **無い場合**: 新規ファイルを作成する。ファイル名は対象を表す英語の kebab-case とする（例: `change-fixed-by-date-preexisting-bugs.md`）

### Step 3: 裏取り（必須工程・省略不可）

記載する内容は、書く前にすべて裏を取る。裏が取れなかった記述は書かない。どうしても言及が必要なら「未確認」と明示する。

- **パスの実在確認**: `paths` と本文に書くファイルパスがすべて実在するか確認する。入力メモに書かれていても実在しないものは訂正し、メモに無くても関連する実ファイルがあれば追加する
- **コミットの確定**: `git log --all -- <path>` で該当の変更が入ったコミットを特定し、`git show --stat --name-only <sha>` で実際に変更されたファイルを確認する
- **PR の状態確認**: 関連ブランチがあれば `gh pr list --head <ブランチ名> --state all` で PR 番号とマージ状態を確認する。未マージなら本文にその旨と、マージ前にバグ修正へ着手する場合の注意を書く
- **ライブラリ由来の主張の確認**: ライブラリの挙動を根拠にする場合は `package.json` でバージョンを、必要なら `node_modules` 配下の実ファイルで挙動を確認し、確認したファイルパスを本文に残す

本文に書く「現状の挙動」は、実測で確認したものと、コードを読んで導いたものを区別して書く。

### Step 4: ルールファイルの生成

`${CLAUDE_SKILL_DIR}/references/format-bug-rules.md` の雛形に従って執筆する。特に次を必ず満たす。

- frontmatter の `paths` に、対象の実装ファイルと対応するテストファイルを列挙する
- 冒頭に**削除条件**（何が満たされたらこのファイルを削除してよいか）を明記する
- 修正がコード上に痕跡を残していない場合は「一次情報は本ドキュメントを正とする」旨を明記する
- 現状の挙動を固定する pin テストがある場合は「バグを直すと pin テストは必ず RED になる。テストを消さず期待値を書き換える」旨と、書き換え対象のテストを各バグの節に書く

時点依存の情報を書く節の日付は、当日日付を使う。

```bash
date '+%Y-%m-%d'
```

### Step 5: 確認と書き込み

生成する内容の要約を提示し、承認を得てから書き込む。要約には次を含める。

- 保存先の絶対パス
- 新規作成か、既存ファイルへの追記かの別
- バグの件数と各バグの見出し
- 裏取りで訂正した点

引数に `-y` が含まれる場合はこの確認をスキップして書き込む。

書き込み後、保存先の絶対パスを報告する。
