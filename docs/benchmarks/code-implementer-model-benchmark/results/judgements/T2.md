findings:
- バグ: ShiftBoardScheduleCards.vue は observe を onMounted のみで行うが、root 要素は `v-if="scheduleIds.length > 0"` で後から生成・再生成される。空→非空になったセルの新要素は観測されず（アンロード機能が無音で無効化）、さらに ghost 状態（isRendering=false）で空→非空を跨ぐと再計測 watch が再度折りたたむのに新要素は未観測のため、画面内に戻してもカードが永続的に非表示になる。要件2・5・6に抵触（参照実装はこの理由で template ref を watch している）
- バグ寄りの不備: onUnmounted の `unobserve(props.cellKey, cellRef.value)` は解除時に要素を独立再評価しており、unmount 時点で template ref が null 化していると要素への解除が届かない。「登録時に解決した要素を退避し同一参照で解除する」指針に直接抵触（参照実装は onBeforeUnmount + 退避変数で回避）
- 実効性の欠陥: ShiftBoardTable.vue の `useIntersectionObserverStore({ rootMargin: '200px' })` は root 未指定（viewport）のまま。対象要素は内側のスクロールコンテナ（.shift-board__body）でクリップされるため viewport root の margin 拡張では交差扱いにならず、先読みは実質機能しない。「チャーンを抑える」というコメントが実装と乖離しており、コメントの因果厳密一致の指針にも反する
- リスク: `watch(() => props.scheduleIds, ...)` は親テンプレートで `getScheduleIdsByDateAndPosition(...)` の戻り値を直接バインドした prop を監視しており、参照安定性の保証がない。参照が再レンダーごとに変わる場合、ghost セル全件が親の再レンダーのたびに remount→実測→unmount を繰り返す（インラインリテラルの参照不安定回避の指針）。実測に clientHeight を使う点も observer コールバック内の強制レイアウトとなり、参照実装の entry.boundingClientRect.height より不利
- 指針違反: `if (!cellRef.value)` / `if (cellRef.value)` の truthiness チェックが複数箇所にあり、Type.isUndefined / Type.isNull ヘルパー統一の規約に不適合
- 指針違反: `:cell-key` の導出 `${row.type}-${row.id}-...` が v-for の `:key`（`${row.type}-${row.id}`）とインライン重複しており、同一性導出の単一集約指針に反する（参照実装は getRowKey へ集約）
- 設計: ShiftBoard.vue が `defineExpose({ closeTooltip })` 経由で子の内部状態を命令的に操作する構成。「所有側で scroll を拾う」点は指針に沿うが、コンテナの prop 渡しや provide と比べ結合が強い。また既存の scoped store 規約（provideXxxScopedStore）があるモジュールで手動 `provide(IntersectionObserverStoreKey, ...)` を選んでおり、共通パターン遵守の面で劣る
- 良い点: display:none の誤検知ガード（getIsHiddenByDisplayNone、要件4）はヘルパー抽出・JSDoc とも適切。既存ストアへの `options` 追加は後方互換でデフォルト挙動不変を JSDoc に明記。isVisible/isRendering 初期値 true の理由コメントも的確

summary:
