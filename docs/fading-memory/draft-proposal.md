## 既存の問題

Claude組み込みのmemoryは忘れる機能がないため、永久に肥大してゆく。
過去の実装に基づく内容や、参照されることがない内容は、適切なタイミングで自動的に削除されるべきである。
他のメモリー永続化系のプラグインでも忘れる機能を提供しているものは少ない

## 用語

- セッション記録：セッションログから抽出したナレッジ
- 記憶データ：セッション記録を元に生成した組み込みのmemory機能と同様に1関心1レコードで記憶した内容
- スコア：記憶データがどれだけ参照されているかの指標
- 有効期限：スコアと作成日から計算した記憶データの有効期限、記憶データの重要度の指標でもある
- 目次：組み込みのmemory機能の `MEMORY.md` に該当する記憶の一覧、重要度順に並ぶ

## 仕様

### セッション記録

- タイトル
  - 作業内容をまとめたもの
  - 最大30行程度
- 作成日時

### 記憶データ

セッション記録を元に生成し、以下の内容を持つ

- タイトル
  - どの様なケースで利用すべき、どんな情報かを簡潔にまとめた内容
  - 目次に使用される
- 再利用可能なナレッジやセッションを跨いで保存しておきたいメモ
  - セッション内の作業中の一時的な情報は入れない
- 作成日時
- 更新日時
- スコア
  - 初期値は0
  - 記憶データが利用された際に+1する
    - 記憶データの再構成時にアクセスした場合はスコアの変動はしない
- 有効期限（要検討）
  - 作成日時のunixtime + スコア * 24 * 60 * 60 * 7
    - スコアが1増えると1週間寿命が伸びる
  - 最大値はInfinity（=忘れてはならないメモ、ユーザーが明示した場合のみ使用する）
- 関連記憶データへのリンク

### 動作

1. セッション終了時にセッション記録を保存する
2. 適切なタイミング（要検討）で記憶データを作成する
3. 定期的に（要検討）記憶データの再構成を行う、目次の更新も行う
4. 定期的に（要検討）、有効期限を過ぎた記憶データを目次から削除する

### セッション記録の保存

- セッション終了時にセッション記録を作成する
  - sonnetとか軽量なモデルを使用する

### 記憶データの再構成

1. 有効期限の遠いもの（=重要度が高いもの）から優先して再構成する
2. 記憶データの情報が正の場合、記憶データはそのまま。再構成は行わない
3. 記憶データの情報が偽の場合、記憶データは削除、目次の更新も行う
4. 記憶データが部分的に正の場合、記憶データを更新する、目次の更新は行わない

### 記憶データの削除

中長期のスパンで有効期限の古いものから削除する
記憶の再構成というよりは、単に容量の肥大化を防ぐ目的

## 検討事項

- 具体的にどの様にデータを記録すべきか
  - 目次はDBにして、記憶データそのものは.mdで保存してしまう
    - その場合、スコアは.md内ではなくDBに保存した方がよさそう
  - 全部DBにする？そうするとAIが自力でmd読めない
- 記憶データが利用された際に+1する仕様で良いか
  - タイトルだけを見て「役に立ちそう」と思われてアクセスされたが、実際は役に立たなかった場合でもスコアが伸びてしまう
  - 「記憶データが役に立った」場合だけ+1する方が本来は良さそう？
- 有効期限の伸び方は線形でよいか
  - スコア1と2の差は本当に情報の重要度として2倍？スコア1と10の差は？
- 有効期限の計算式
  - スコア1増が、7日の期限の延長で本当によいか？
    - 3回参照されたら21日延長はやりすぎ感
- どのタイミングで記憶データを作成するか
  - セッション終了時？
    - その場合はセッション記録はそもそも必要なさそう
- どのタイミングで再構成を行うか
  - セッション終了時に記憶データ作成後に行う？
    - 毎回行わなくて良い
  - 定時実行？
- どのタイミングで削除を行うか
  - セッション終了時？
    - セッション終了時の負担大きくない？
  - 定時実行？
